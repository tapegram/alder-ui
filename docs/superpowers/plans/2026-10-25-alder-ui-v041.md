# alder-ui v0.4.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every open tapegram/alder-ui issue (#6, #8–#15) on branch `fixes-041`, ship it as one PR, and tag `v0.4.1`.

**Architecture:** The fixes are small CSS, JS and test-harness changes to the existing components. Every behaviour change gets a pin from the mechanism that already exists for it:
- `data-expect` rows in `demo/parity.html` pin resting values.
- `data-ref-states` marker pairs pin states (a ref rebuild needs Node).
- `CLOSE_CHECKS` and `ANCHOR_CHECKS` in `test/parity.py` pin overlay behaviour.
- `test/test_page.py`-style Playwright unittests pin viewport, no-JS and forced-colors behaviour.
- Pure unittests pin harness and checker logic.

**Tech Stack:** Plain CSS (`@layer al`), ES-module custom elements, Python 3 stdlib unittest and Playwright (Chromium 156), and the Vite/React shadcn oracle in `ref/`.

**Spec:** the issues themselves (`gh issue view N -R tapegram/alder-ui`, N = 6, 8–15). The code survey `docs/superpowers/plans/2026-10-25-alder-ui-v041-survey.md` gives file:line, current code and pin options for every checklist item. Read the survey section for your issue before you start. Its line numbers are from main @ b4f0a34. The v0.4.0 design spec is in the alder repo at `docs/superpowers/specs/2026-10-24-alder-ui-shadcn-design.md`; its §5.2 covers alert content.

## Global Constraints

- Work on branch `fixes-041` in `~/projects/alder-ui`. Make one commit per task at least, and end every commit message with the session's attribution lines.
- **The gate:** every task ends with all four of these passing:

## Decisions (controller calls, recorded here so tasks don't re-argue them)

- **D1 (#6): anchor with JS in `al-shim.js`; keep the `anchor=` feature.** A probe on Chromium 156 confirmed that `anchor=` is ignored: `p-anchor` sits under its invoker. CSS `position-anchor` and `showPopover({source})` both fix it.
  - The shim listens for `beforetoggle` on `document` (capture). When an `al-popover[anchor]` or `al-menu[anchor]` is opening, it finds the element named by `anchor`. It gives that element a generated dashed-ident in its inline `anchor-name`, appended after any existing value, and sets the popover's inline `position-anchor` to the same name. The ident is generated and cached in a `WeakMap` per target, because ids may not be valid idents.
  - If the id resolves to nothing, the shim clears the popover's inline `position-anchor`, so the implicit invoker anchor applies again.
  - Because the lookup runs at every open, morphs and id changes need no observer.
  - Without `al.js`, `anchor=` does nothing and the popover anchors to its invoker. Document this in the al-popover header and the README.
- **D2 (#11): leave popover `p` leading alone.** The issue's premise is false: twin and ref both compute 20px. Pin it at 20px. Surfaces keep shadcn's per-part values: card/dialog body `p` 24px, descriptions 20px, popover `p` 20px, alert nested `p` `leading-relaxed`. Record this in each surface's header comment. `al-popover > * { margin: 0 }` stays, as shadcn-faithful; document it.
- **D3 (#14): no-JS labels get the line variant but no pill.**
  - Implement `al-tabs[variant=line]` for the radio labels: the checked label has a transparent background, no shadow, and the built line tab's underline indicator.
  - The muted pill is not feasible, because the labels and panels share one flex container. Document that limit in the README and the `al-tabs.css` header.
- **D4 (#15): fix forced colors with `@media (forced-colors: active)` blocks, not by changing normal-mode outlines.** Normal-mode computed styles stay exactly as they are, so parity is unaffected.
  - Menu keyboard focus also gets a normal-mode non-colour indicator on `:focus-visible` only: `outline: 2px solid var(--muted-foreground); outline-offset: -2px`. That divergence gets allow entries.
  - The dialog title gets `padding-inline-end: 1.5rem` back when the dialog is dismissible. That is the close button's 1rem plus a 0.5rem gap; the implementer confirms the exact value against the button rect. It gets a `dialog/title/open` `padding` allow entry.
- **D5 (#9.3, #13.7): add real ref markers and rebuild the ref.** This covers menu item states and the pagination ellipsis. Do not substitute `data-expect`.
- **D6 (#13.8): mirroring a flipped popover or menu origin is not possible without JS.** `@position-try` cannot carry `transform-origin` or `translate`, and a container query cannot restyle its container. Document the limit in al-popover.css and al-menu.css. Do make the menu origin RTL-aware with a `:dir(rtl)` rule (`top right`).
- **D7 (#10.6): fix the comment, not the rule.** The renderer always emits the header before the description.
- **D8 (#8.5): delete both dead wildcard allow entries.** Add an unused-allow-entry WARN, which is never a failure and is skipped under `--only`.

## Review Focus

1. **`anchor=` pointing at a missing, removed or renamed id**, including after a morph: the popover opens anchored to its invoker, with no exception. *Task 1 pins this.*
2. **An anchor target that already has an author `anchor-name`:** the author's name survives, and both names resolve. *Task 1 pins this.*
3. **RTL:** the menu transform-origin and the dialog title's inline-end padding must follow `dir=rtl`. *Tasks 5 and 7 pin this.*
4. **Forced-colors blocks must not leak into normal mode.** Parity stays green with no new allow entries, except D4's menu and dialog-title ones. *Task 7's gate shows this.*
5. **The unused-allow WARN must not fire on `--only` runs.** It must also not fire on entries that a light-only or dark-only diff uses. *Task 2 pins this.*

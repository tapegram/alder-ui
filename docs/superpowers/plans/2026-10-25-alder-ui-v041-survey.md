- `collect()` (580-624): per theme, reads ref+twin markers (`READ_JS` 233-253, PROPS 67-73), opens each overlay group one at a time on the twin, drives states (hover/focus via `Page.drive` 363-382), then `EXPECT_JS` rows. Rows are `(component, marker, theme, state, prop, ref, twin)`.

### data-expect rows (twin-only pins, no shadcn counterpart)
- Attribute `data-expect="prop: value; prop: value"` (and `data-expect-before` for ::before) on any twin element WITHOUT `data-ref`.
- `EXPECT_JS` (parity.py 255-277): selector `[data-expect]:not([data-ref]), [data-expect-before]:not([data-ref])`; component = nearest `al-*` ancestor-or-self minus `al-` (else `page`); label `<comp>/expect/<localName>-<n>[::before]`; values compared with `diff()` against the computed style (same colour/size tolerance as the grid; sizes 0.5 px).
- Failures are reported as rows with state `expect`, gate like any component (even if the component has no data-ref markers, `report` prints them, see ReportTest).
- Example rows (demo/parity.html): line 70 `<al-input label="Name" data-expect="height: 58px">...`; 71 `<ul class="errors" ... data-expect="display: none">`; 128 `<p slot="description" data-expect="line-height: 20px">` / 129 `<p data-expect="line-height: 24px">Card body text.</p>`; 152 `<al-alert ... data-expect="height: 46px">`; 289+ flow rhythm rows `data-expect="margin-top: 24px"`.
- Constraint: demo/parity.html may not use `<style>` or `style=`; layout only with `al-page`/`al-stack`.
- Hover/focus are NOT drivable via data-expect: it reads the resting computed style only. State pins need a `data-ref` marker with `data-ref-states`, a CLOSE/ANCHOR-style custom check, or a test_page-style Playwright test.

### Twin rows: Alder markup vs ref markup
- Both pages carry the same marker strings. Twin: `data-ref="<component>/<variant>/<state-or-size>"` on the box that draws the look (inner `<button>`, `<input>`, `<dialog>`...). Ref: same attribute in `ref/src/App.tsx` on the shadcn component.
- `data-ref-states="hover focus"` must be identical on both (check_sets 645-649 compares lists). Overlays: `data-ref-open` on both; the twin is opened (showModal/showPopover) one group at a time (OPEN_JS 291-297).
- Pseudo-element markers (twin only): `data-ref-before|after|backdrop="<marker>"` map the marker to ::before/::after/::backdrop (the ref's real element carries the plain `data-ref`).
- Tabs are tagged at load by the inline script in demo/parity.html lines 22-37 from `data-ref-tablist`, `data-ref-tab-selected`, `data-ref-tab` on `al-tabs`.
- `check_sets` (635-650): any marker on one page only, or state lists differing, is fatal. So adding a ref marker means adding the twin marker in the same commit, and vice versa.
- `test/parity-allow.json` shape: `{"pending": [], "map": {twinMarker: refMarker}, "allow": [{"ref": glob, "prop": glob, "reason": text}]}`. Example: `{"ref": "dialog/overlay/open", "prop": "box-*", "reason": "structural: ..."}`. `map` e.g. `"alert/info/root": "alert/default/root"`.
- Property names compared: PROPS (color, background-color, border-*, box-shadow, font-*, line-height, letter-spacing, padding, height, gap, opacity, outline, text-decoration) plus synthetic `box-width`, `box-height` (and `width` for FIXED_WIDTH globs, lines 74-77).

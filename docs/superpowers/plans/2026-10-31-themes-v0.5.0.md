# alder-ui v0.5.0: starting themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** alder-ui ships five starting themes as DTCG token files under `themes/`, a theme-wide `--al-border-width` token, a `themes` check (structure, Zinc parity, AA contrast), a theme select on the showcase, and the v0.5.0 tag.

**Architecture:** One small stdlib module, `scripts/dtcg.py`, reads a theme directory (resolver + three token files) and converts each token to CSS text. `test/check.py` uses it to validate every theme and to run the existing contrast check over each theme's resolved colours; `scripts/showcase.py` uses it to inline one `<style>` block per theme under a class on `<html>`. `tokens.css` stays hand-written and is the reference Zinc is held to.

**Tech Stack:** CSS, Python 3.12 stdlib (check, build, showcase), Playwright only for the existing parity and browser tests.

**Spec:** `~/projects/alder/docs/superpowers/specs/2026-10-31-theme-presets-design.md` on alder branch `theme-phase-3-spec` (https://github.com/tapegram/alder/blob/theme-phase-3-spec/docs/superpowers/specs/2026-10-31-theme-presets-design.md). Sections that matter here: "The five starting themes", "The one component-library change", "The DTCG files in alder-ui", Appendix A.

## Global Constraints

- DTCG format version `2025.10`; resolver `$schema` is `https://www.designtokens.org/schemas/2025.10/resolver.json`.
- Theme order everywhere (showcase select, check output): `zinc`, then `brutal`, `catppuccin`, `paper`, `pebble`.
- Each theme dir holds exactly `theme.resolver.json`, `base.tokens.json`, `light.tokens.json`, `dark.tokens.json`; `themes/catppuccin/` also holds `LICENSE` (Catppuccin's MIT notice).
- Token name = CSS custom property without `--`: `color.primary-foreground` is `--primary-foreground`, `width.al-width-narrow` is `--al-width-narrow`, `border.al-border-width` is `--al-border-width`. Groups carry `$type`; nothing else is read from them.
- Every token carries a one-sentence `$description` saying what it colours or sizes.
- Value forms: colour `{colorSpace, components[3], alpha?, hex?}`; dimension `{value, unit: "px"|"rem"}`; fontFamily string or array; shadow object `{color, offsetX, offsetY, blur, spread, inset?}` or array of them; alias `"{group.name}"`.
- Token set per theme = exactly the set `tokens.css` declares, excluding `--color-white`, `--color-black` and `--_al-*`: 15 theme-wide (base) and 32 colours (light and dark each).
- **Key order is load-bearing** (alder builds its table in file order). Base order: `radius, radius-sm, radius-md, radius-lg, radius-xl, al-width-narrow, al-width-normal, al-width-wide, font-sans, font-mono, shadow-xs, shadow-sm, shadow-md, shadow-lg, al-border-width`. Colour order: `background, foreground, card, card-foreground, popover, popover-foreground, primary, primary-foreground, secondary, secondary-foreground, muted, muted-foreground, accent, accent-foreground, destructive, destructive-foreground, border, input, ring, chart-1 … chart-5, sidebar, sidebar-foreground, sidebar-primary, sidebar-primary-foreground, sidebar-accent, sidebar-accent-foreground, sidebar-border, sidebar-ring`. This is alder's current table order, not `tokens.css`'s block order (the spec's "order against tokens.css" is superseded by "golden CSS stays as it is"; alder's goldens follow its table).
- `--al-border-width` default `1px`; Brutal `2px`. Only borders use it: `outline*`, `block-size: 1px`/`height: 1px` separators, `calc(100% - 1px)` keep literals.
- AA tuning rule, in order and no further: (1) swap the pair's foreground to the theme's dark or light text colour; (2) move the background's oklch L by at most ±0.08 and C by at most ±0.03; never change a hue. List each change in the PR body. A pairing that cannot pass goes back to the user with both candidates rendered: stop and ask.
- `check.py`, `build.py`, `showcase.py`, `dtcg.py` stay stdlib-only and run on Python 3.12.
- After any source change, `python3 scripts/build.py` rebuilds `al.css`, `al.js`, `index.html`; CI's bundle check fails otherwise.

## Review Focus

- A theme file with a trailing comma or other invalid JSON: `check.py` reports a FAIL naming the file and line, not a traceback.
- A Zinc colour written with alpha (`--border` dark is `oklch(1 0 0 / 10%)`): the Zinc parity check treats `alpha: 0.1` as equal to `/ 10%`, not as a mismatch.
- Brutal's shadows alias a colour that lives in the scheme files (`{color.border}` from `base.tokens.json`): alias resolution looks across the merged base + scheme tokens, and the showcase's Brutal shadows flip with dark mode.
- A user who saved `localStorage.theme = "dark"` before and then picks Paper: the showcase keeps dark mode and paints Paper's dark values.
- An unknown `localStorage` theme name (a theme later removed): the showcase falls back to Zinc without a console error.

Each line has a test in the owning task below.

### Task 2: `scripts/dtcg.py`, the DTCG → CSS converter

**Files:**
- Create: `scripts/dtcg.py`
- Test: `test/test_dtcg.py`

**Interfaces:**
- Produces:
  - `class DTCGError(Exception)` — message names the file and (for JSON errors) the line.
  - `load_theme(dir: Path) -> Theme` where `Theme` is a dataclass `{name: str, description: str, base: dict[str, Token], light: dict[str, Token], dark: dict[str, Token]}` and `Token` is a dataclass `{css: str, type: str, value: object, description: str, file: str}`; dicts preserve file key order; keys are CSS names with `--`.
  - `css_value(tok: Token, scope: dict[str, Token]) -> str` — the CSS text; `scope` is the merged tokens used to resolve aliases (base + one scheme).
  - `resolved(theme: Theme) -> tuple[dict[str,str], dict[str,str], dict[str,str]]` — `(common, light, dark)` CSS-name → CSS text, the shape `check.contrast_table` takes.

- [ ] **Step 1: Write the failing tests** in `test/test_dtcg.py`, using `tempfile` dirs:
  - `test_oklch_colour`: `{"colorSpace":"oklch","components":[0.3,0.03,50]}` → `"oklch(0.3 0.03 50)"`.
  - `test_alpha`: oklch `[1,0,0]` with `alpha: 0.1` → `"oklch(1 0 0 / 0.1)"`.
  - `test_srgb_hex`: srgb with `hex: "#eff1f5"`, alpha absent → `"#eff1f5"`; srgb `[0,0,0]` alpha `0.05` no hex → `"rgb(0 0 0 / 0.05)"`.
  - `test_dimension`: `{"value":0,"unit":"rem"}` → `"0"`; `{"value":0.5,"unit":"rem"}` → `"0.5rem"`.
  - `test_font_array`: `["Geist", "ui-sans-serif"]` → `'"Geist", ui-sans-serif'` (quote any family that is not a CSS generic or keyword-like identifier, the same way `tokens.css` writes `--font-sans`).
  - `test_shadow_layers`: two layers, second `inset: true` → `"0 1px 2px 0 rgb(0 0 0 / 0.05), inset 0 0 0 1px #000000"` (each part by its own rule).
  - `test_alias_colour_is_var`: `ring: "{color.primary}"` in a scheme file → `"var(--primary)"`; `test_alias_in_shadow`: a base shadow whose `color` is `"{color.border}"` → contains `var(--border)`.
  - `test_alias_unresolved`: `"{color.nope}"` raises `DTCGError` naming `color.nope`.
  - `test_bad_json_names_file_and_line`: a file with a trailing comma raises `DTCGError` whose message contains the file name and `line`.
  - `test_order_preserved`: `list(theme.light)` equals the file's key order.
  - `test_type_inherited`: a token without `$type` under a group with `$type: color` reads as `color`; `test_type_mismatch`: `{"$type":"color"}` group holding a dimension value raises `DTCGError`.
- [ ] **Step 2: Run** `python3 -m unittest test.test_dtcg -v` — FAIL (module missing).
- [ ] **Step 3: Implement** `scripts/dtcg.py`. Read the resolver, follow its `sets.base.sources[*].$ref` into `base`, and `modifiers.scheme.contexts.light|dark[*].$ref` into `light`/`dark`; refs are relative to the dir and must not contain `..` or be absolute. Walk groups recursively with `json.loads(..., object_pairs_hook=...)`-style ordered dicts (plain dicts already keep order in 3.12); a key starting `$` is metadata. Numbers print in shortest form (`repr(float)` trimmed: `0.3`, `50`, never `.3` or `50.0`). On `json.JSONDecodeError` raise `DTCGError(f"{file}: line {e.lineno}: {e.msg}")`.
- [ ] **Step 4: Run** the tests — PASS.
